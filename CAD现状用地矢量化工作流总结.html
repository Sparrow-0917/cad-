3. 配准阶段结论

  • 两张图的 500 m 比例尺均已恢复为 500 CAD units。
  • 底图作为绝对基准锁定。
  • 参考图只用于空间判读，不再进行重复配准。
  • 禁止非等比例拉伸、透视变形和橡皮片式强制贴合。
经验：老地形图与较新卫星现状图可能存在年代、制图概化和局部投影差异。不要为追求“视觉完全重合”破坏真实尺度。

5. AutoLISP 辅助

  1. 将 LISP 保存为 UTF-8。
  2. AutoCAD 输入 APPLOAD。
  3. 加载 现状用地绘制工具.lsp。
  4. 运行 XZYD_SETUP 创建/检查图层和图例。

中文建议：LISPSYS = 1，图例文字使用宋体或其他系统中文字体，优先采用 MTEXT。

图例对象最好统一放在“现状用地-图例”图层；色块用对象 TrueColor，这样便于整体移动、隐藏和置顶。

6. 精确描边规则

  1. 放大原现状图，先确认真实色块边界。
  2. 在 CAD 使用 PLINE 逐点描边。
  3. 明显转折必须保留，不能用少数大节点粗略概括。
  4. 最后输入 C 闭合。
  5. 先检查边界，再填色。
  6. 相邻图斑尽量共边，避免明显缝隙和重叠。
  7. 道路、河流、桥梁、建成区边缘作为重要几何约束。
禁止：用大三角形/梯形替代真实边界；跨越道路、河流；为了少节点而明显改变地块形状。

7. 边界判断优先级

  1. 原现状图明确色块边缘
  2. 道路边缘
  3. 河流、水系边缘
  4. 明显建成区边缘
  5. 其他稳定地物

仍无法可靠判断时，宁可暂时跳过，也不要强行绘制错误边界。

8. 填充与绘图次序

描边 → 闭合检查 → 图层检查 → SOLID填充 → Draw Order调整 → 局部校核
  • 边界：闭合 Polyline。
  • 填充：SOLID HATCH。
  • 颜色：优先 ByLayer。
  • Hatch 置于边界线下方，边界保持可见。

9. 图例置顶

使用对象绘图次序，而不是“图层置顶”。

DRAWORDER → 选择图例对象 → Front（置于最前）

对象较多时，可先用 QSELECT 按“现状用地-图例”图层批量选择。

10. Remote Desktop Commander 工作流

原生 Computer Use 出现 Computer Use native pipe is unavailable 后，改用 Remote Desktop Commander 作为本机文件、终端和进程控制桥梁。

启动

npx -y @wonderwhy-er/desktop-commander@latest remote

出现 Device ready 后保持 PowerShell 窗口开启。

  • ChatGPT 网页端可直接使用已连接的 Remote Desktop Commander。
  • VS Code 中 Codex 的远程 MCP OAuth 曾出现兼容性问题，当前优先网页端。
  • 它适合文件、终端、脚本和进程控制；视觉描边仍应配合 AutoLISP 与人工校核。

12. 错误成果重绘流程

  1. 只删除上一轮错误生成的 Polyline、Hatch 和错误图斑。
  2. 严禁删除原底图、参考图、图例和既有图层。
  3. 回到原始现状参考图重新判读，不在错误成果基础上修修补补。
  4. 建议分为北部、中北部、中部核心区、西部、南部、东南部逐区重绘。
  5. 每完成一个分区立即对照原图校核。
核心原则：宁可少画，也不要画错。

13. 保存策略

01_底图与现状图精准配准.dwg        ← 原始基准，不覆盖
04_现状用地重绘_清理完成.dwg      ← 错误成果删除后
05_现状用地重绘_阶段成果.dwg      ← 分区完成后
06_现状用地精准重绘.dwg           ← 最终成果

14. 最终检查清单

  • 原底图、参考图未移动、未缩放、未重新配准。
  • 未重复创建同类图层。
  • 主要图斑均为闭合 Polyline。
  • R2、工业、公共服务、绿地、水域边界与原图一致。
  • 高速、国道、河流两侧图斑不存在跨越错误。
  • 相邻图斑无明显重叠和大缝隙。
  • Hatch 为 SOLID、ByLayer，并位于边界线下方。
  • 图例颜色、文字与实际图层一致。
  • 阶段成果和最终成果均已保存。

15. 一句话工作法

底图锁定 → 原图判读 → 分图层逐区描边 → 闭合校核 → SOLID填充 → 分区复核 → 阶段保存 → 最终检查。
